# bukang-devops 설계

크루런 팀(Linear BUK 팀)의 티켓 일정과 기한을 한눈에 보는 조회 전용 대시보드예요.
크루런 모노레포 안의 `devops/` 폴더에 있지만, 저장소는 개인 GitHub(`Jieunsse/bukang-devops`)으로 따로 관리하고 Vercel에 배포해요.
팀 저장소는 `.git/info/exclude`로 이 폴더를 보지 않아요.

## 누가, 무엇을

- 보는 사람: 크루런 팀원 다섯 명. 로그인 없이 주소로 들어와요.
- 티켓은 앱에서 보기만 해요. 티켓 수정은 Linear에서 해요.
- 예외로 달력의 「일정 보기」에서는 팀 일정을 앱 안에서 추가·수정·삭제할 수 있어요(11/6 지훈 결정). 보기는 누구나, 바꾸기는 팀 비밀번호를 넣은 사람만 할 수 있어요.
- 예외로 「작업 요청」 페이지에서는 팀원을 골라 Linear 티켓을 새로 만들 수 있어요(11/6 지훈 결정). 기존 티켓은 고치지 않고, 팀 비밀번호를 넣은 사람만 만들 수 있어요.
- 가져오는 범위: Linear BUK 팀 전체 티켓(보관된 티켓 제외).
- 검색엔진 수집은 막아요(`robots.txt` 전체 차단 + `noindex`).

## 기술

- Next.js(App Router), TypeScript strict, Tailwind CSS, HeroUI
- TanStack Query(서버 데이터), Zustand(필터 등 화면 상태), Zod(Linear 응답·환경변수 검증), React Hook Form(필터 입력)
- 얕은 FSD: `app/`, `widgets/`, `features/`, `entities/`, `shared/` 다섯 층만 써요.
- 테마: HeroUI 기본 테마 그대로, 밝은 화면과 어두운 화면 모두 지원하고 기기 설정을 따라가요.
- 외부 API는 Linear GraphQL API와 Firebase(Firestore) 두 가지예요. 따로 띄우는 백엔드 서버는 없고, Next.js 서버 함수(Vercel)가 둘을 불러요.
- 팀 일정은 Firestore `schedules` 모음에 저장해요. 서버만 Firebase Admin(서비스 계정)으로 읽고 써요. 브라우저가 Firestore에 바로 들어오는 읽기·쓰기는 보안 규칙(`firestore.rules`)으로 모두 막아요.
- 팀 비밀번호는 서버 환경변수 `SCHEDULE_PASSWORD`에만 두고, 서버에서 시간 차이가 드러나지 않는 방식으로 비교해요. 틀리면 저장하지 않아요.

## 데이터와 캐싱

- Linear API 키는 서버 환경변수 `LINEAR_API_KEY`에만 둬요. 브라우저로 내려가지 않게 `NEXT_PUBLIC_`를 붙이지 않아요.
- 서버: 팀의 끝나지 않은 티켓과 사이클을 한 번에 받아 `unstable_cache`(태그 사용)로 10분 동안 저장해요. 사람 수와 상관없이 10분에 많아야 한 번 Linear를 불러요.
- 브라우저: 서버가 처음 그린 데이터를 TanStack Query가 이어받아요(`staleTime` 10분, `refetchOnWindowFocus: false`). 다시 방문하면 브라우저 저장소에 남긴 목록을 먼저 보여 주고 뒤에서 새로 받아요(보관 하루).
- 필터는 받아 둔 목록을 브라우저에서 걸러요. 필터를 바꿔도 Linear를 부르지 않아요.
- 앱 안의 「새로고침」 버튼은 서버 캐시를 비우고 Linear에서 새로 받아요. 브라우저 새로고침과 달라요. 서버 전체에서 1분에 한 번만 동작하고, 그 안에 누르면 「방금 새로 받았어요(n초 전)」라고 알려 줘요.
- 화면에 마지막으로 받은 시각을 보여 줘요.
- 대시보드는 완료·취소 티켓을 받지 않아요. 완료·취소 티켓은 그 페이지에 들어갈 때만 따로 받아요.

## 기간 기준

- 날짜는 모두 한국 시간 기준이에요.
- 「이번 주」는 지금 사이클이에요. 사이클이 없는 기간이면 오늘부터 이번 주 일요일까지를 「사이클 밖 기간」으로 보여 줘요.
- 묶음은 서로 겹치지 않아요.
  - 기한 지남: 어제까지 기한이고 끝나지 않은 티켓
  - 오늘: 오늘이 기한
  - 이번 주: 내일부터 이번 주(사이클 또는 사이클 밖 기간) 끝까지
  - 그 뒤: 이번 주 다음
  - 기한 없음

## 화면 생김새

- HeroUI 공식 대시보드 템플릿(https://heroui.com/en/themes?template=dashboard, 캡처 `docs/references/heroui-dashboard-template.png`)과 최대한 비슷하게 만들어요.
- HeroUI 컴포넌트를 최대한 그대로 써요. 직접 만든 컴포넌트는 HeroUI에 없는 것(타임라인 막대 등)만 둬요.
- 템플릿에서 가져올 것: 왼쪽 메뉴(위에 앱 이름, 아래에 도움말), 연한 회색 바탕 위 흰 카드, 숫자 요약 카드 네 칸, 큰 카드 두 개를 나란히, 아래에 필터·정렬 버튼이 있는 표, 오른쪽 위 새로고침 아이콘 버튼과 주 버튼.
- 템플릿 자리에 우리 내용을 넣어요: 숫자 카드 = 기한 지남·오늘·이번 주·기한 없음, 큰 카드 두 개 = 사람별 남은 티켓(막대)·마일스톤 진행률, 표 = 마감 목록, 위 탭 = 대시보드 안 묶음 전환.
- 버튼·선택·차트는 HeroUI 기본 강조색(파랑)을 써요. 상태를 뜻하는 색은 기한 세 단계(지남 빨강, 오늘 주황, 그 밖 회색)에만 써요.

## 페이지

왼쪽 메뉴로 네 페이지를 오가요. 필터 버튼은 네 페이지 공통이고, 페이지를 옮겨도 유지돼요.

### 공통 머리 영역

- 앱 이름 `bukang-devops`, 오른쪽에 최종 발표(2026-11-23)까지 남은 날짜(D-n)
- 그 아래 줄: 지금 사이클 이름과 기간(사이클 밖이면 「사이클 밖 · 11/5~11/8」), 마지막으로 받은 시각, 새로고침 버튼, 필터 버튼

### 필터

- 담당자, 라벨, 마일스톤
- 고른 값은 주소에 남겨요(`?assignee=...&label=...&milestone=...`). 링크로 같은 화면을 공유할 수 있어요.

### 1. 대시보드 (첫 화면)

배치(HeroUI 템플릿 기준, 11/5 확정): 맨 위 탭으로 마감 묶음을 바꿔요. 그 아래 숫자 요약 네 칸, 그 아래 사람별 남은 티켓 카드와 마일스톤 진행률 카드를 나란히, 맨 아래 마감 목록 표. 휴대폰에서는 한 줄로 쌓여요.

- 숫자 요약: 기한 지남, 오늘, 이번 주, 기한 없음. 칸을 누르면 마감 목록이 그 묶음만 보여 줘요.
- 마감 목록(11/5 변경, 접힌 묶음이 세로로 길게 늘어서서 바꿈): 전체 보기에서는 묶음마다 카드 하나를 가로로 나란히 둬요. 넓은 화면에서는 기한 지남·오늘 카드를 크게 위에, 이번 주·그 뒤·기한 없음 카드를 작게 아래에 놓아요. 태블릿은 두 줄, 휴대폰은 한 줄이에요.
  - 카드 한 줄에는 번호, 제목, 담당자 프로필, 기한을 적어요. 카드마다 5건까지 보여 주고, 넘으면 「n건 더 보기」를 둬요. 0건인 카드는 「없어요」만 보여 줘요.
  - 카드 머리줄이나 「전체 보기」·「n건 더 보기」를 누르면 그 묶음을 골라요. 그러면 카드 대신 그 묶음 티켓 전부를 아래 표로 보여 줘요. 위쪽 탭과 숫자 칸으로 골라도 같아요. 「묶음 선택 풀기」를 누르면 카드로 돌아와요.
  - 표 한 줄: 제목, 이슈 번호, 담당자, 기한, 라벨, 마일스톤. 누르면 Linear 이슈로 이동해요.
  - 기한 표시: 기한 지남은 「3일 지남」 빨강, 오늘은 「오늘」 주황, 그 밖은 「11/12 (D-3)」 회색. 라벨·마일스톤 칩은 회색 한 톤이에요.
  - 마일스톤이 없는 티켓은 「마일스톤 없음」으로 적어요.
- 사람별 남은 티켓: 담당자마다 티켓 수를 「기한 지남, 이번 주, 그 뒤」로 나눈 막대. 담당자 없는 티켓은 「담당 없음」 줄. 막대를 누르면 그 사람으로 필터가 걸려요.
- 마일스톤 진행률: Linear가 주는 진행률을 낮은 순으로 전부, 남은 티켓 수와 함께. 맨 아래 「마일스톤 없음 n건」. 누르면 그 마일스톤으로 필터가 걸려요.

### 대시보드 추가 (11/5 지훈 요청)

- 달력 카드: HeroUI 달력으로 한 달을 보여 주고, 날짜마다 그날 기한인 끝나지 않은 티켓 수를 날짜 원 오른쪽 위의 작은 배지 숫자로 표시해요(11/5 변경, 날짜 밑 작은 숫자가 날짜의 일부처럼 읽혀서 바꿈). 배지는 기한이 지난 날 빨강, 오늘 주황, 그 밖 회색이에요. 티켓이 없는 날은 배지를 두지 않아요. 날짜를 누르면 아래 마감 목록이 그날 기한인 티켓만 보여 줘요. 다시 누르면 풀려요. 최종 발표일(11/23)은 파란 테두리, 사이클 기간은 연한 회색 바탕으로 표시해요. 사이클 바탕을 회색으로 둬서 파란 「오늘」 바탕과 헷갈리지 않게 해요. 카드 제목은 「달력」이에요. 카드 아래 범례 줄은 두지 않고, 날짜에 마우스를 올리면 「최종 발표」, 「사이클 기간」, 「기한인 남은 티켓 n건」 중 그날에 맞는 뜻을 툴팁으로 보여 줘요(11/5 변경). 「크게 보기」는 연한 바탕의 작은 버튼이에요.
- 밝은·어두운 화면 전환 버튼: 왼쪽 사이드바 아래쪽(도움말 자리)에 둬요(11/5 변경, 머리 영역에서 옮김). 기본값은 기기 설정이고, 고른 값은 브라우저에 기억해요.
- 최종 발표 남은 날짜: 머리 영역 구석의 작은 글자 대신 대시보드 맨 위에 크게 보여 줘요. 「최종 발표 11/23(월)까지 18일」을 큰 숫자로 쓰고, 프로젝트 시작일(10/28)부터 발표일까지 지난 비율을 막대로 함께 보여 줘요.

### 달력 페이지 (11/5 지훈 요청)

- 대시보드의 작은 달력을 크게 보는 상세 페이지예요. 왼쪽 메뉴에 「달력」을 더하고, 대시보드 달력 카드에 「크게 보기」 링크를 둬요.
- 생김새는 큰 월간 달력(macOS 캘린더 월 보기, 캡처 `docs/references/calendar-page-reference.webp`)이에요. 한 주가 한 줄이고, 날짜 칸이 넓어요. 한 주는 일요일에 시작해 토요일에 끝나요(티켓 보기·일정 보기 같음).
- 토요일·일요일은 요일 머리글과 날짜 숫자를 빨강으로 써요(11/6 지훈 요청). 바탕은 칠하지 않아 오늘(주황 동그라미)·기한 지남 표시와 헷갈리지 않아요. 앞뒤 달 주말 날짜는 흐린 빨강이에요.
- 날짜 칸마다 그날 기한인 끝나지 않은 티켓을 한 줄씩 보여 줘요. 한 줄은 「이슈 번호 + 제목(말줄임)」이고, 앞에 담당자를 구분하는 색 막대를 붙여요. 누르면 Linear 이슈로 이동해요.
- 칸에 다 들어가지 않으면 「n건 더」를 두고, 누르면 그날 티켓 전체를 작은 창으로 보여 줘요.
- 기한이 지난 날의 티켓은 빨강, 오늘은 주황으로 표시해요. 사이클 기간은 연한 바탕, 최종 발표일(11/23)은 칸 위에 「최종 발표」 표시를 둬요.
- 이전 달·다음 달 이동과 「오늘」 버튼을 둬요. 공통 필터(담당자·라벨·마일스톤)가 그대로 적용돼요.
- 완료·취소 티켓은 보여 주지 않아요(대시보드와 같은 데이터를 써서 Linear를 다시 부르지 않아요).

#### 일정 보기 (11/6 지훈 요청)

- 달력 도구 줄에서 「티켓 보기」와 「일정 보기」를 골라요. 처음에는 「티켓 보기」이고, 그 화면은 위 설명 그대로예요.
- 「일정 보기」는 팀이 직접 넣은 개발 일정을 같은 월간 달력에 보여 줘요. Linear에서 가져오지 않아요.
- 일정 하나는 제목(60자까지), 기간(시작일·종료일), 색이에요. 하루짜리는 두 날짜를 같게 넣어요.
- 기간은 브라우저 기본 날짜 창 대신 HeroUI 기간 선택기를 한국어로 써요. 종료일이 시작일보다 빠르면 저장하지 않고 「종료일이 시작일보다 빨라요」라고 알려 줘요. 서버도 같은 규칙으로 다시 검사해요.
- 색은 파랑(기본)·초록·보라·청록·회색 중 하나예요. 빨강·주황은 티켓 기한 뜻이라 쓰지 않아요. 고르는 칸에는 색 이름을 함께 적고, 막대는 옅은 색 바탕과 진한 왼쪽 띠로 그려요. 글자는 늘 기본 글자색이라 밝은·어두운 화면 모두 읽혀요. 색이 없는 예전 일정은 파랑으로 보여요. 기간 일정은 시작일부터 종료일까지 날마다 칸에 보여요.
- 「일정 추가」 버튼이나 일정을 눌러 창을 열고(날짜 칸의 빈 곳을 두 번 누르면 그 날짜가 채워진 추가 창이 열려요), 팀 비밀번호를 넣어 저장·삭제해요. 삭제는 한 번 더 눌러야 지워져요. 창 바깥을 누르거나 「닫기」, Esc로 닫아요. 단, 창이 열린 직후 0.5초 동안은 바깥을 눌러도 닫히지 않아요(일정을 두 번 누를 때 두 번째 누름으로 창이 바로 닫히지 않게 하려고요). 한 번 넣은 비밀번호는 페이지를 떠날 때까지 기억하고, 브라우저 저장소에는 남기지 않아요.
- 일정 막대를 끌어 다른 날짜 칸에 놓으면 옮겨져요. 기간 일정은 잡은 날짜에서 놓은 날짜까지 떨어진 날 수만큼 시작일과 종료일이 함께 옮겨져요. 저장 응답을 기다리지 않고 바로 새 자리에 보여 주고, 거절되면 원래 자리로 되돌려요. 이 페이지에서 비밀번호를 아직 넣지 않았으면 옮긴 날짜가 채워진 고치기 창을 열어 비밀번호를 물어요. 키보드 사용자는 일정을 눌러 고치기 창에서 날짜를 바꿔요.
- 반복 일정, 알림, 참석자는 없어요.
- Firebase 값이 없는 로컬 개발 서버에서는 서버 메모리에 저장해서, 서버를 다시 켜면 사라져요. Vercel(운영·미리보기)에서 값이 없으면 오류를 내요.

### 작업 요청 페이지 (11/6 지훈 요청)

- 왼쪽 메뉴 맨 아래에 「작업 요청」이 있어요.
- 「누구에게」에서 요청받을 팀원을, 「요청하는 사람」에서 나를 골라요. 팀원 목록은 Linear BUK 팀 멤버예요.
- 제목(100자까지)은 꼭 적고, 설명(2000자까지)과 기한은 고르지 않아도 돼요.
- 받는 사람이 다시 채우지 않게 분류도 요청하는 사람이 정해서 보내요(11/6 지훈 요청).
  - 프로젝트·라벨(하나 이상)·우선순위(긴급·높음·보통·낮음)·사이클은 꼭 골라요. 사이클은 「사이클 없음」도 고를 수 있어요.
  - 마일스톤은 고른 프로젝트의 마일스톤 중에서 고르고, 처음에는 「마일스톤 없음」이에요.
  - 프로젝트가 하나뿐이면 미리 골라 둬요. 끝났거나 취소된 프로젝트, 지난 사이클, 묶음 라벨은 보기에 넣지 않아요.
  - 보기는 Linear에서 받아 서버가 10분 동안 나눠 써요. 서버는 받은 보기 밖의 값이나 다른 프로젝트의 마일스톤이 오면 만들지 않아요.
  - 상태는 고르지 않고 팀 기본 상태(Backlog)로 만들어요.
- 「요청 보내기」를 누르면 고른 팀원이 담당자인 티켓이 BUK 팀에 만들어져요. 기한을 고르면 티켓 기한이 돼요.
- Linear에는 API 키 주인이 만든 사람으로 찍혀요. 그래서 설명 끝에 「요청한 사람: 이름 (부캉이 작업 요청)」을 적어요.
- 팀 비밀번호는 일정과 같은 `SCHEDULE_PASSWORD`예요. 서버가 비밀번호, 값, 두 사람이 BUK 팀 멤버인지를 다시 확인한 뒤에만 만들어요.
- 만들면 「BUK-n 티켓을 만들었어요」 알림과 「Linear에서 보기」 버튼이 나오고, 서버 캐시를 비워 대시보드에 바로 보여요. 양식은 비우고 요청하는 사람만 남겨요.
- `LINEAR_API_KEY`가 없는 로컬 개발 서버에서는 Linear에 보내지 않고 「BUK-예시」로 만든 척만 해요.

#### 요청 내역 (11/9 지훈 요청)

- 양식 아래에 이 페이지로 보낸 요청을 최근 것부터 보여 줘요. 비밀번호 없이 팀 누구나 볼 수 있어요.
- 표로 보여 줘요. 칸은 제목(누르면 Linear), 번호, 요청한 사람, 받는 사람, 상태, 요청 시각이에요. 설명 본문은 보여 주지 않아요.
- 「요청 내역 n건」 제목을 누르면 표를 접고 펼쳐요. 처음에는 펼쳐 있어요.
- 요청한 사람과 받는 사람 모두 프로필 이미지와 실명을 함께 보여 줘요. 받는 사람은 대시보드처럼 Linear 닉네임 대신 실명으로 바꾸고, 요청한 사람은 같은 실명의 팀원에게서 프로필 이미지를 가져와요.
- 설명 끝 「(부캉이 작업 요청)」 표시로 찾아요. 그래서 이 기능 전에 보낸 요청도 나오고, 끝났거나 취소된 요청도 나와요. Linear에서 설명의 요청한 사람 줄을 지우면 내역에서 빠지거나 요청한 사람이 「알 수 없음」으로 나와요.
- 최근 100건까지 보여 줘요. 서버가 10분 동안 나눠 쓰고, 새 요청을 보내면 바로 다시 받아요.

### 2. 사이클

- 탭: 사이클 밖 기간(있을 때) / 사이클 1 / 사이클 2 …
- 위에 진행률(완료 수 / 전체 수), 아래에 담당자별로 묶은 티켓 목록(기한 순)

- 기한 없는 티켓은 빼고 「기한 없음 n건」만 표시해요.
- 줄 묶음: 담당자별(기본) / 마일스톤별 전환 버튼
- 세로선: 오늘, 최종 발표일(11/23). 마일스톤에는 목표일이 없어서 마일스톤 마감선은 그리지 않아요.
